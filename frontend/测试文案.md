# NL2SQL 前台测试文案

> 服务已启动。前端访问：**http://localhost:5174** ｜ 后端：http://localhost:8000 ｜ Swagger：http://localhost:8000/docs
> 顶部 `user_id` 默认 `default`，无需改动。DB 默认选中 `california_schools`。

## 场景 1 ｜基础查询：时间轴逐个点亮 + 结果表格

**操作**
1. 顶部确认 DB = `california_schools`
2. 底部输入框输入：`查询学校总数`
3. 回车（或点"发送"）

**预期**
- 左侧助手卡片内**时间轴按顺序逐个点亮**：信息检索 → 可回答性（可回答 · conf=0.95）→ SQL 生成（N 候选 SQL）→ 执行（N 候选 · M 成功）→ 最终决策（选中 xxx）→ 结果（1 行结果）
- 首次访问该库时卡片内显示蓝色提示"首次加载该数据库，约需数秒…"
- **结果区**：上方 SQL 代码块 `SELECT COUNT(*) FROM schools;` + 复制按钮；下方表格 `COUNT(*) = 17686`，分页"共 1 条 / 10 条/页"
- 右侧**检查器自动跟随**最新节点（顶部"自动跟随"标签），展示该节点结构化详情
- **qwen3 思考链**区域（折叠态）显示 `cg xxxx 字` / `decision xxxx 字`，点开可看打字机式思考过程

## 场景 2 ｜缓存命中短路

**操作**：在场景 1 完成后，再次输入同一查询：`查询学校总数`，回车

**预期**
- 时间轴**仅点亮"缓存检测 · 缓存命中 · session_history · conf=1.00"**，跳过信息检索/可回答性/SQL生成/执行/决策
- 触发**反问气泡**："检测到历史相似查询，是否复用？" + 输入框 + 提交按钮
- ⚠️ 已知现象：因后端 cache_confirm 机制同时 emit 了 error 事件，时间轴会多出一个"错误"节点（内容是 Interrupt 的 repr）。这是**后端 bug，非前端问题**，不影响下方 resume。

---

## 场景 3 ｜反问 resume 续流（承接场景 2）

**操作**：在反问气泡输入框填 `是`，点"提交"

**预期**
- 时间轴在反问节点**之后继续追加**节点（最终决策 · 选中 cache_hit / 结果）
- 检查器状态从"等待反问回答"→"推理中"→"已完成"
- 最终出现结果表格（COUNT(*)=17686）
- ✅ 验证 D4：整个 resume 过程 `turnId` 不变（同一轮气泡），后端 `query_id` 已换新

---

## 场景 4 ｜会话管理（建/列/历史/删）

**操作**
1. 点左侧栏"**新会话**"按钮 → 侧栏顶部新增一个会话（0 轮）
2. 点侧栏里**之前的会话**（2 轮那个）→ 对话区加载历史轮次（显示"历史结果 · 1 行" + SQL + 表格）
3. 点某会话右侧**删除图标** → Popconfirm 点"确定" → 侧栏移除该项

**预期**
- 会话列表按 `updated_at` 降序，每项显示 session_id（截断）、状态、轮数、时间
- 当前选中会话高亮
- 删除当前会话会自动切到首个剩余会话或空态

- 加载完成后正常推进推理 → 出结果

## 场景 7 ｜检查器交互：点击 pin + 思考链

**操作**（在场景 1 查询进行中或完成后）
1. 点时间轴某个节点（如"SQL 生成"）→ 检查器**锁定**显示该节点详情，顶部标签变"已锁定：候选生成"
2. 此时即使有新节点完成，检查器不再跟随
3. 再点同一节点 → 取消锁定，恢复"自动跟随"
4. 展开思考链面板 → 内容自动滚到底部（打字机效果）

**预期**
- 点 pin / 取消 pin 切换正常
- 锁定态下检查器内容不随新节点变化
- 思考链展开后滚动到底，折叠/展开切换正常
- 无思考链事件时（非思考模型）不显示思考链区域

## 已知问题（非阻塞）

1. **后端 cache_confirm 双发事件**：缓存命中反问时同时 emit clarification + error，前端如实渲染"错误"节点。修复在后端（见 `memory/backend-cache-confirm-emits-error.md`）。
2. **AntD 弃用警告**（控制台）：`Spin tip`、`Table rowKey index`、静态 `message`。不影响功能。
