## ADDED Requirements

#### Scenario: 使用 EXPLAIN 验证安全执行 SQL
给定来自 CG 模块的已验证 SQL 候选
当执行引擎在实际执行前运行 EXPLAIN 时
则它应该捕获并解析 EXPLAIN 输出以进行查询计划分析
并且它应该仅在 EXPLAIN 成功时才执行实际查询
并且它应该限制执行时间以防止长时间运行的查询

#### Scenario: 捕获并结构化执行错误
给定在执行期间失败的 SQL 查询
当执行引擎捕获错误时
则它应该提取错误类型（语法、语义、运行时）
并且它应该识别具体的问题元素（表、列、操作）
并且它应该格式化错误信息以供 LLM 在修正循环中使用

#### Scenario: 实现错误修正循环
给定带有结构化错误的失败 SQL 执行
当执行引擎启动修正循环时
则它应该向 LLM 提供错误上下文和原始查询
并且它应该允许最多 2 次修正尝试
并且它应该在 2 次尝试后仍有错误时终止修正

#### Scenario: 支持多种数据库后端
给定 BIRD-SQL 数据集中的不同数据库格式（SQLite、MySQL）
当执行引擎连接数据库时
则它应该自动检测并使用适当的连接方法
并且它应该处理特定于数据库的 SQL 方言差异
并且它应该在所有后端之间保持一致的错误报告
