## ADDED Requirements

#### Scenario: 将检索到的 schema 转换为 M-schema 格式
给定由 IR 模块检索到的一组表和列
当 SS 模块将其转换为 M-schema 格式时
则它应该包含表名、列名、数据类型和样本值
并且它应该在可用时保留外键关系
并且它应该按照 CHESS M-schema 规范进行格式化

#### Scenario: 使用 LLM 过滤不相关的列
给定一个来自多个表的包含 20+ 列的 M-schema
当 SS 模块使用 few-shot 示例评估列相关性时
则它应该仅保留与查询意图直接相关的列
并且它应该在列选择中实现精度 > 0.9
并且它应该在 3 秒内完成评估

#### Scenario: 处理多表查询
给定一个需要跨 3+ 表进行 JOIN 操作的查询
当 SS 模块处理 M-schema 时
则它应该识别 JOIN 所需的所有表
并且它应该包含每个表中仅与 JOIN 相关的列
并且它应该保留外键信息以构建正确的 JOIN

#### Scenario: 保留关键元数据
给定一个包含重要约束或描述的 schema
当 SS 模块过滤列时
则它应该保留主键标识符
并且它应该维持有助于 SQL 生成的列描述
并且它不应该丢失对查询正确性至关重要的数据类型信息
