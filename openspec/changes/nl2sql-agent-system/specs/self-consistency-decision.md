## ADDED Requirements

#### Scenario: 多个候选 SQL 执行结果一致时的决策
给定 5 个 SQL 候选的执行结果，其中 3 个返回相同结果
当 self-consistency 模块进行投票决策时
则它应该识别出结果一致的候选组
并且它应该从一致组中选择执行时间最短的 SQL 作为最终结果
并且它应该输出该 SQL 及其执行结果

#### Scenario: 所有候选结果不同时的 LLM 决策
给定 5 个 SQL 候选，每个都返回不同的结果
当 self-consistency 模块进行投票决策时
则它应该调用大模型进行最终决策
并且它应该向大模型提供所有候选 SQL、执行结果和执行时间
并且它应该接受并输出大模型选择的最佳 SQL 和结果

#### Scenario: 处理全部执行失败的情况
给定 5 个 SQL 候选全部执行失败
当 self-consistency 模块进行投票决策时
则它应该返回错误信息给用户
或者它应该触发重新生成机制尝试新的 SQL 生成

#### Scenario: 记录决策过程和依据
当 self-consistency 模块完成决策时
则它应该记录最终选择的原因（一致性投票或 LLM 决策）
并且它应该在 LangSmith 中追踪决策链路
并且它应该输出各候选 SQL 的执行时间和结果对比
