## ADDED Requirements

#### Scenario: 使用实体掩码生成多个 SQL 候选
给定一个包含命名实体（如"苹果公司"）的自然语言查询
当 CG 模块应用实体掩码并生成 SQL 时
则它应该用适当的占位符替换实体
并且它应该生成最多 5 个多样化的 SQL 候选
并且它应该基于查询模式使用相关的 few-shot 示例

#### Scenario: 验证 SQL 安全性和语法
给定包含各种操作的生成 SQL 候选
当 CG 模块验证这些候选时
则它应该拒绝任何包含危险操作（INSERT、UPDATE、DELETE、DROP 等）的 SQL
并且它应该使用 sqlglot 解析器验证语法
并且它应该仅将语法正确且安全的 SQL 传递给执行引擎

#### Scenario: 处理多表 JOIN 查询
给定一个需要多表连接的高级查询
当 CG 模块选择 few-shot 示例时
则它应该仅使用训练集中的多表 JOIN 示例
并且它应该基于外键生成正确的 JOIN 条件
并且它应该在所有候选中保持查询语义

#### Scenario: 优化可读性和效率
给定同一查询的多个有效 SQL 候选
当 CG 模块确定最终候选时
则它应该在可能时优先选择更简单的查询结构
并且它应该避免不必要的子查询或复杂表达式
并且它应该保持一致的格式以便于调试
